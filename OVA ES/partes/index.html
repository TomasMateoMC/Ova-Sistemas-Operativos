Entrada / Salida (E/S) en un sistema operativo

Cómo el sistema operativo controla los dispositivos de la computadora, desde el hardware hasta los programas del usuario.

Introducción Hardware de E/S Software de E/S Simulador

1. Introducción

Una de las funciones principales del sistema operativo es el control de todos los dispositivos de E/S (teclado, disco, impresora, red, entre otros). Para lograrlo debe:

  • Enviar comandos a los dispositivos.
  • Detectar las interrupciones.
  • Controlar los errores.
  • Ofrecer una interfaz sencilla y, de preferencia, igual para todos los dispositivos (independencia del dispositivo).

El código de E/S es una parte importante del sistema operativo, y usar mal los dispositivos puede causar ineficiencias que reducen el rendimiento de todo el sistema.

Idea clave:

El sistema operativo actúa como intermediario entre el hardware y los programas, ocultando las diferencias entre dispositivos y ofreciendo una interfaz uniforme.

2. Principios del hardware de E/S

La interfaz del hardware indica qué comandos acepta, qué funciones realiza y qué errores puede informar.

Dispositivos de bloque y de carácter

De bloque

Guardan información en bloques de tamaño fijo. Cada bloque tiene una dirección y se puede leer o escribir de forma independiente. Ejemplo: los discos.

De carácter

Transfieren un flujo de caracteres, sin bloques ni direcciones. Ejemplos: impresoras de línea, terminales, interfaces de red y ratones.

Hay excepciones: los relojes no tienen bloques con dirección ni generan flujos de caracteres. El sistema de archivos trabaja con dispositivos de bloque abstractos; los detalles del dispositivo quedan a cargo del software manejador.

Controladores de dispositivos

Una unidad de E/S tiene un componente mecánico y uno electrónico, llamado controlador o adaptador. El sistema operativo se comunica con el controlador, no directamente con el dispositivo.

El controlador intercambia bits con el dispositivo, organiza los datos, comprueba errores y los copia a memoria. Sus registros reciben comandos y parámetros del sistema operativo. Cuando termina una operación, el controlador provoca una interrupción.

Acceso directo a memoria (DMA)

Sin DMA: el controlador lee el bloque en su buffer y provoca una interrupción; después la CPU copia el bloque a memoria byte por byte, ocupando tiempo de procesamiento.

Con DMA: la CPU indica la dirección del bloque, la dirección de memoria destino y cuántos bytes transferir. El controlador hace la copia y provoca una sola interrupción al terminar.

El buffer interno permite almacenar los datos mientras se transfieren, incluso si el bus está ocupado.

Factor de separación

En algunos discos, mientras un controlador simple transfiere un sector a memoria, el siguiente sector puede pasar bajo la cabeza y perderse. Para evitarlo, al formatear se numeran los bloques dejando uno o más espacios entre ellos; así el sistema puede leerlos en orden a la máxima velocidad posible.

3. Principios del software de E/S

Organización en capas

Las capas inferiores ocultan las peculiaridades del hardware y las superiores ofrecen una interfaz más sencilla:

Proceso del usuario: realiza llamadas de E/S, da formato a los datos y puede usar spooling.
Software independiente del dispositivo: gestiona nombres, protección, buffers y asignación.
Manejadores de dispositivos: escriben en los registros del controlador y verifican su estado.
Manejadores de interrupciones: atienden la interrupción y desbloquean el proceso que esperaba.
Hardware: realiza la operación física de E/S.

Objetivos del software de E/S

  • Independencia del dispositivo: un programa puede funcionar con archivos en distintos dispositivos sin modificarse.
  • Nombres uniformes: archivos y dispositivos se direccionan mediante nombres y rutas.
  • Manejo de errores: se resuelven lo más cerca posible del hardware y se notifican a niveles superiores si es necesario.
  • Transferencias síncronas o asíncronas: la E/S suele ser asíncrona, aunque el sistema operativo puede presentarla de forma sencilla y síncrona a los programas.
  • Dispositivos compartidos o exclusivos: los discos suelen compartirse; una impresora puede requerir acceso exclusivo.

Manejadores de interrupciones

El proceso que inicia una operación de E/S puede bloquearse hasta que esta termina. Cuando llega la interrupción, el manejador correspondiente atiende el evento y desbloquea el proceso.

Manejadores de dispositivos

Este software depende del dispositivo. Recibe solicitudes abstractas, las convierte en operaciones concretas, escribe comandos en el controlador, espera la interrupción, revisa errores y atiende la siguiente solicitud de la cola.

Software independiente del dispositivo

Proporciona una interfaz uniforme a los manejadores y se ocupa de nombres, protección, buffers, bloques de tamaño uniforme, asignación e informes de errores. En muchos sistemas, cada dispositivo se identifica con un nodo-i que incluye un número principal (el manejador) y uno secundario (la unidad).

Software de usuario y spooling

Una parte pequeña del software de E/S está en bibliotecas enlazadas a los programas; la mayor parte pertenece al sistema operativo. El spooling se usa con dispositivos de acceso exclusivo: los procesos dejan sus archivos en un directorio de spooling y un proceso especial, llamado demonio, los envía al dispositivo. Así, un proceso no retiene la impresora mientras prepara todo el trabajo.
